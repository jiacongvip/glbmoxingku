**核心原则**：版型（轮廓、肩线、插肩、袖长、袖姿、下摆、领口）+ 领型 = **锁死不变**；只换花色与配色。同一套系的 01/02/05/06 必须彼此一致。

## 三、生成流水线（照抄即可）

### 3.1 接口

```bash
# 主通道 duomi（异步）
POST https://duomiapi.com/v1/images/generations
GET  https://duomiapi.com/v1/tasks/{id}      # running / succeeded / failed；600s 过期

# 备通道 heju（同步，返回 b64_json）
POST https://www.hejuapi.com/v1/images/generations
```

- key 存在淘宝店数据库：`ddwx_digitalavatar_provider_config`（provider_key = `duomiapi` / `hejuapi`）
- 取 key：
  ```bash
  docker exec tpdaxiangshop_mysql sh -c 'mysql -uroot -p"$MYSQL_ROOT_PASSWORD" -N --raw -e \
    "select api_key from ddwx_digitalavatar_provider_config where provider_key=\"duomiapi\"" tpdaxiangshop'
  ```
- 模型：`gpt-image-2.5-flare`（主力）、`gpt-image-2`（备，便宜但质感弱）
  - `gpt-image-2.5-sunburst`：长期「系统繁忙」，别用
  - `flare` 在 2048 有时「系统繁忙」，重试或降 1024
- 传图：接口只吃 URL，需先传 CDN
  ```bash
  docker cp file.png tpdaxiangshop_php:/tmp/x.png
  docker exec tpdaxiangshop_php php /app/runtime/k85_oss_upload.php /tmp/x.png _suffix
  # → https://qiniuoss.changzhouyunshan.com/upload/YYYYMM/…
  ```
  > 若 `/app/runtime/k85_oss_upload.php` 丢失（店铺重部署会清），用
  > `docker exec tpdaxiangshop_php cp /app/_kit27_upload/oss_upload.php /app/runtime/k85_oss_upload.php` 恢复。

### 3.2 出图规范（非常重要）

1. **背景必须纯品红 `#FF00FF`**，并写「人物/衣服四周不要发光、光晕、阴影或渐变」。
   - 直接要「透明底」不行；要白底则模型会加光晕，抠图必带毛边。
2. **色键抠图用 despill 版**（`key_magenta.py`）：
   - 判洋红 `m = min(r,b) - g`，`alpha = clip((hi-m)/(hi-lo))`，`hi=70, lo=15`
   - 边缘把 r/b 拉向 g 去粉边，再内缩 1px + 轻微模糊
   - ⚠️ 若花色本身含洋红/玫红（如 58），阈值要收紧到 `(r>225)&(b>225)&(g<90)`
3. **尺寸锁定**：等比缩放，内容装进 1838×1886 的框，居中到 2000×2000 的 (81,57)。
   - 不要拉伸！比例特殊的（如 42 宽高比 0.96）按 min 缩放留边
4. **锐化**：放大后 `UnsharpMask(radius=2.0, percent=90, threshold=2)`
5. **金属/深色类**（如 53 黑刮痕、50 深蓝）出图仍可能偏软，可再 `radius=2.2, percent=110`

### 3.3 三类图的提示词骨架

**A. 正面 2D**（图1=底版，图2=该套旧正面/设计稿）
```
上衣正面打板产品图（XX号 rN）。
图1 = 【底板模板】，唯一版型标准：整件版型（轮廓/肩线/插肩/袖长/袖姿/下摆/构图）+ 领子结构 ——
     全部与图1完全一致，一个像素都不许改。
图2 = 花色【只取花色与配色】：<描述颜色与纹样>
要做的：把图2花色铺到图1版型上；领子保持图1，只换内衬颜色。
禁止：禁止重画领子/改领口大小/改下摆/把袖子放下来；禁止出现图2没有的杂色；禁止文字/号码/logo。
背景必须是纯品红 #FF00FF…无人体模型，无文字，无阴影。
```

**B. 背面 2D**（图1=背面通用底板，图2=该套**新正面**取花色）
```
球衣【背面】打板产品图（XX号）。
图1 = 背面底板：轮廓/袖姿/后颈领圈带/插肩线 全锁；
图2 = 该套正面成品，只取花色。
禁止加领口开口、门襟、扣子、胸前图案。
```

**C. 3D 上身**（05：图1=新正面，图2=旧 05；06：图1=背面，图2=旧 06）
```
整套球衣【上身效果图】· 正面。
图1 = 最新正面成品（花色/配色/领型严格照它）
图2 = 参考图（姿势/黑短裤/白长袜/黑球鞋/构图照它）
只把上身球衣换成图1这件；领口严格照图1，别加黑领圈/门襟扣子
【画面质感】4K 产品摄影，清晰锐利，不要糊、不要噪点
【构图】人物占满画面，高度约 92%~96%
背景纯品红 #FF00FF
```
> 3D 若用 1024 出图人物只有 ~380px 宽，放大必糊 → **必须 2048**，并强调「占满画面 + 大块花纹（6~8 条）+ 清晰锐利」。

## 五、踩过的坑（血泪清单）

1. **额度极易见底**：每套 1–2 张，duomi 经常「余额不足或没有权限」，heju 见底会报「预扣费额度失败」。出图前先探一张。
2. **不要让模型自己「重画领子」**：它会改形状。要么给底版锁死，要么给领子素材 1:1 装。
3. **底板必须是干净的纯色衣身**：早期「底板模板-57领子灰身」里残留了狼头/棋盘格/袖条，导致整套出图被污染。
4. **不要手工拼底板**：用手 P 的底板会被判不合格（用户明确反对），要么模型生成，要么从设计稿里抠出领子再装。
5. **文字描述微结构会反效果**：写「袖口细黑收边/插肩缝深色线/两侧无竖条」会让模型乱加细节 —— 正确写法是「禁止改图1的袖口/插肩缝/两侧处理方式」。
6. **领口/领子会被放大**：要给数值约束（如「领子宽度约衣宽 28%」），否则模型普遍放大 50%+。
7. **flare 爱加发光**：prompt 里必须写「禁止外发光/光晕/边缘白光」，否则白底抠不干净。
8. **色键会吃花色**：套系本身是玫红/洋红时（58），阈值必须收紧，否则衣服被抠穿。
9. **一版一版对比看**：每版存 `_过程稿/` + `meta-01-rN.json`，用户回退时能立刻找回。
10. **`/tmp` 会被清**：脚本要落到 `_工具/`，不要只放 `/tmp`。

  "cdn_url": "<上传后的 url>",

## 七、另一个项目：数字商城 App UI（`_ui/`）

用户要的移动端数字资产商城首页（深蓝+橙、磨砂玻璃、数藏平台质感）。

- **做法**：写 HTML/CSS → Chrome headless 截图（比生图模型更清晰，文字不会乱）
  ```bash
  "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
    --headless=old --disable-gpu --no-sandbox --hide-scrollbars \
    --user-data-dir=/tmp/chrome-x --window-size=1080,3660 \
    --screenshot=app-1080.png "file://$PWD/app.html"
  ```
- 成品：`_ui/app-1080.png`（1080×3660 长图）、`_ui/app.html`（源文件，改文案/配色重渲染即可）
- 另一版单屏：`_ui/mall.html` → `mall-1080x2280.png`（1080×2280，9:19）
- 注意：`html,body{height:...}` 必须与截图 `--window-size` 一致；flex 子项要 `flex:none` 否则会被压缩；`margin-top:auto` 的底部导航要求内容高度小于画布，否则被顶出画面。
